# AI System Design — шаблон MVP

Шаблон для секции AI System Design (2 часа): ревью RFC джуна → работающий MVP через curl →
код руками. Заточен под GPT-6-Luna Fast на Medium: агент сразу пишет простой синхронный
код по готовым образцам, а production-архитектура и НФТ живут в [spec.md](spec.md) и [plan.md](plan.md).

**Стек:** FastAPI · SQLAlchemy 2 (sync + async, psycopg 3) · Alembic · PostgreSQL 18 + pg_trgm ·
Redis · RustFS (S3) · очередь задач в PostgreSQL + пул воркеров · httpx + tenacity · JWT.

## Подготовка (до интервью)

```bash
make init              # .venv для IDE + сборка образа
make up                # PostgreSQL, Redis, RustFS, api, worker; миграции
make demo              # happy path через curl — всё зелёное
# browser demo: http://localhost:8000/demo
make ai                # Codex: один раз одобрить хуки ai-logs в /hooks, затем выйти
make timer SPEED=60    # посмотреть таймер (2 часа за 2 минуты); закрыть — ПКМ или make stop
make stop              # остановить всё и стереть данные: интервью начнётся с чистых БД
```

## На интервью

Идеал: за первые 35 минут заполнить [spec.md](spec.md) и [plan.md](plan.md) так, чтобы агенту
хватило **одного промпта** «Реализуй plan.md». Этапы разделены нестрого: секцией управляет
кандидат, spec и plan можно дописывать и после 35'.

1. `make start <name>` — ветка `<name>`, чистые `ai-logs/`, сервисы, таймер с 00:00.
2. `make ai` — **новая** сессия Codex: хуки ai-logs подхватываются только при старте сессии.
3. **Дизайн (0–35):** ревью RFC → spec.md — **полная** система под всю нагрузку (ФТ, НФТ, расчёты,
   архитектура, замечания к RFC). Затем **перемычка** (см. ниже) → plan.md: MVP.
4. **Реализация (35–80):** «Реализуй plan.md» → агент делает все шаги с curl-проверками и
   `make demo`. Пока он работает — комментируем решения, смотрим curl, правим точечными промптами.
5. **Код руками (80–100):** `manual/solution.py`, `python3 manual/solution.py`. Агент в это время
   может доделывать MVP.
6. **Финал (110–120):** `make stop` — проверка секретов, commit + push ветки, стереть БД и S3,
   остановить всё, вернуться на `main`.

## Перемычка СД → MVP (2 минуты)

Артефакт СД — не финал: впереди кодинг, времени мало. После полной схемы в spec.md явно скажи:
«У нас осталось X минут. Давай зафиксируем MVP под happy path и перейдём к реализации».
Дальше за пару минут сворачиваешь схему до одного сервиса + worker, одной PostgreSQL, Redis и S3
(таблица замен prod → MVP — в [AGENTS.md](AGENTS.md)), **сохраняя логику работы сервиса**:
те же сущности, статусы и потоки, только на простой инфраструктуре. Это дискуссионная часть —
проговори, что режешь и почему, и запиши в раздел 0 plan.md.

## plan.md

- **0. Перемычка** — что оставляем, режем, заменяем.
- **1. Демо** — happy path: действие → ответ.
- **2. PostgreSQL** — таблицы SQL `CREATE TABLE` (типы, NOT NULL, DEFAULT, UNIQUE, FK, индексы);
  агент переносит их в `app/models.py` один-в-один.
- **3. HTTP API** — ручки `/api/v1/...`: тело запроса → код и тело ответа, ошибки; 🔒 — нужен JWT.
- **4. Нюансы** — транзакции, фоновые задачи (kind + payload), кэш, статусы.
- **5. Шаги** — действие + curl-проверка с ожидаемым результатом; последний — `make demo`.

В шаблоне plan.md — образец по коду шаблона (users, items, files, auth): замени на свою задачу.

## Промпты

- Дизайн: «Заполни spec.md по RFC ниже: списками, коротко.» + текст RFC
- Дизайн: «Заполни plan.md по spec.md: перемычка, SQL-таблицы, ручки /api/v1, нюансы, шаги.»
- Реализация: **«Реализуй plan.md.»** — все шаги по очереди с проверками
- Реализация: «Добавь поле X в Y: модель, миграция, API. Проверь curl.»
- Ошибка: «`curl …` вернул 500, в `make logs`: <traceback>. Почини.»
- Финал: «Допиши в plan.md раздел „Не сделано / риски“ по факту кода.»

## Какая модель и reasoning

**GPT-6-Luna Fast Medium** — по умолчанию: на «MVP по готовому plan.md» она уже укладывалась
в ~1,5 минуты (таблица ниже). Если на большом plan.md Luna начнёт ошибаться — запасной вариант
`make ai M=gpt-6.1-sol E=low` (новый основной workhorse OpenAI; сравнение на полном plan.md
в новом формате ещё не прогонялось).

**Reasoning везде Medium** (по умолчанию в `.codex/config.toml` и `make ai`). Low можно выбрать
для быстрых простых шагов через `make ai E=low`. High не нужен:
на документах он в 2,5 раза медленнее без выигрыша в качестве.

Бенчмарк 27.09.2026, GPT-6-Luna Fast, `codex exec` на чистой копии репозитория; каждый прогон
проверялся независимым curl-скриптом. Все 22 прогона прошли проверку, тесты агент не писал ни разу.

| Задача (один промпт) | Low | Medium | High |
|---|---|---|---|
| Поле `priority` в items: модель, миграция, API | 28 с | 28 с | 40 с |
| Сокращатель ссылок: таблица, POST, 302-редирект, кэш в Redis | 37 с | 44 с | 41 с |
| MVP по готовому plan.md: 4 шага, воркер кликов, demo.sh | 74 / 80 с | 84 с | 104 с |
| spec.md + plan.md по RFC джуна (расчёты, ошибки RFC) | 58 / 70 с | 63 / 73 с | 161 с |
| Доставка вебхуков одним промптом: fan-out, ретраи, статусы | 78 с | 94 с | 128 с |
| Отладка: воркер не берёт задачи | 26 с | 27 с | 23 с |

Скоростной профиль Codex (без субагентов, плагинов, MCP и веб-поиска) на время почти не влияет
(сокращатель на Medium: 44 с с профилем, 40 с без), но убирает соблазн уйти в субагентов.

## Команды

- `make init` — один раз: `.venv` для IDE и сборка образа
- `make start <name>` — старт интервью: ветка, чистые ai-logs, сервисы, таймер
- `make stop` — финиш: commit + push ветки, стереть БД/S3, остановить всё, вернуться на `main`
  (вне интервью — просто остановить всё и стереть данные)
- `make up` · `make build` — поднять всё · пересобрать образ после `uv add <пакет>`
- `make logs` — логи api и worker за 5 минут
- `make migration m="..."` · `make migrate` · `make psql` — миграции, консоль PostgreSQL
- `make demo` · `make test` · `make fmt` — curl-сценарий · pytest · ruff
- `make ai [M=gpt-6.1-sol] [E=low]` — Codex (GPT-6-Luna Fast Medium по умолчанию); в сессии — `/model`
- `make timer [SPEED=60 AT=35]` — таймер без сброса; с параметрами — тестовый прогон

API: http://localhost:8000/docs · browser demo: http://localhost:8000/demo · консоль S3:
http://localhost:9001 (rustfsadmin / rustfsadmin).

## Как устроено

- **Код** — `app/`: публикации и лента в `api/posts.py` и `api/feed.py`, браузерное демо в
  `api/demo.py`, `auth.py` (регистрация и вход по email + пароль, JWT), помощники в `infra/`.
  Правила для агента — [AGENTS.md](AGENTS.md) (`CLAUDE.md` импортирует его).
- **Очередь вместо Kafka** — таблица `jobs`: `queue.enqueue()` в той же транзакции (outbox даром),
  воркер забирает задачи через `FOR UPDATE SKIP LOCKED`, повторяет с backoff, после 5 попыток — `failed`.
- **Таймер** — окно без рамки поверх всех окон (и fullscreen) на основном мониторе: этап
  с подсказкой, обратный отсчёт до конца этапа, общее время, шкала этапов; жёлтый фон —
  последние 2 минуты этапа.
  Тащится мышью; двойной клик — компактный режим; ПКМ — пауза, ±1 минута, сброс.
- **ai-logs** — хуки Codex и Claude пишут `ai-logs/PROMPTS.md` и `ai-logs/sessions/` только
  во время активной тренировки в её ветке, с этапом таймера и маскированием секретов.
- **Codex** — `.codex/config.toml`: Luna Fast Medium, без подтверждений, без субагентов, плагинов,
  MCP и веб-поиска. Хуки ai-logs Codex доверяет по пути и хешу: после правки `.codex/hooks.json`
  их нужно заново одобрить в `/hooks`.
